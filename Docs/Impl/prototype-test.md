# プロトタイプの確認手順

## 実施済みの検証

実施日は2026-09-14。Unity 2022.3.22f1同梱Roslynと、同じUnityのEditor／Engine DLL・.NET Standard 2.1参照を使い、`Editor`配下の全8 C#ファイルをEditor用DLLとしてコンパイルする。

- 実行: `& ./Tools~/compile.ps1`
- 結果: **終了コード0、警告0、エラー0**（警告もエラーとして扱う設定）。
- 対象: `dennokoworks.MatSync.Editor`の全ソース。ダミーのUnity APIやスタブは使用しない。
- ログ: [compile.log](../../Temp~/Compile/compile.log)
- 実際のUnityプロジェクト全体の再コンパイル、ウィンドウ操作、描画、Undo操作、性能測定は実施していない。下記はユーザーによる確認用手順である。

## 準備

1. Unity 2022.3.22f1 / lilToon 2.3.4の環境で、スクリプトのインポート完了を待つ。ConsoleにMatSync由来のコンパイルエラーがないことを確認する。
2. テスト用としてlilToonの`.mat`アセットを3つ複製し、`MatSync_A`、`MatSync_B`、`MatSync_C`とする。
3. 3つに異なるMain Textureを設定する。BとCのTiling／Offsetをそれぞれ異なる値にする。
4. Aの基本色を赤、Bを青、Cを緑にし、影の使用状態やMatCapの強度も異なる値にする。元の値を控える。
5. 検証用のメッシュにB、Cを割り当てる。複数スロットのメッシュ、SkinnedMeshRenderer、非アクティブな子メッシュも用意できると抽出確認をまとめて行える。
6. **Tools → dennokoworks → MatSync** を開く。

## 1. マテリアル指定と抽出（AC-01〜03、AC-23）

1. コピー元にAを、コピー先へBとCをProjectからまとめてドロップする。
2. 同じBとCを再度ドロップする。リストの件数が増えないことを確認する。
3. Aをコピー先へドロップする。コピー元と同じ参照が除外されることを確認する。
4. 一度リストをクリアし、Hierarchyの複数メッシュを同時にドロップする。全スロット・子階層・非アクティブな子から重複なく追加されることを確認する。
5. 不要な1行を「×」で除外する。Materialアセットが削除されず、Rendererの割り当ても変化しないことを確認する。
6. コピー元に複数の候補があるメッシュをドロップする。候補メニューを閉じると現在の元を維持し、1件を選ぶとそのMaterialに切り替わることを確認する。
7. RendererがないGameObjectや空スロットを含むメッシュを渡し、理由が表示されることを確認する。

## 2. 標準コピーとUndo／Redo（AC-04、AC-06、AC-21）

1. 元をA、先をB・Cとし、「テクスチャを含める」がOFFであることを確認する。
2. 「コピー」を押す。B・Cの基本色、影の使用状態、MatCap強度などがAにそろうことを確認する。
3. B・Cのテクスチャ参照とTiling／Offsetは、各々の元の値を保つことを確認する。Aは変更されない。
4. Unityの **Edit → Undo** を1回実行する。B・Cが両方ともコピー前に戻ることを確認する。
5. **Edit → Redo** で両方に再適用されることを確認する。
6. 同じ設定でもう一度コピーする。「変更なし」と表示され、不要なUndo履歴が増えないことを確認する。

## 3. テクスチャ込みコピー（AC-05）

1. 「テクスチャを含める」をONにしてコピーする。
2. B・Cのテクスチャ参照とTiling／OffsetがAと一致することを確認する。
3. Aの任意のテクスチャスロットを未設定にして再コピーし、そのスロットも未設定になることを確認する。
4. Undoで各コピーを戻せることを確認する。

## 4. ブロック比較と適用（AC-09〜12）

1. A・Bの影、MatCap、リムライトを異なる値にする。
2. 比較モードで左A・右Bを指定し、比較ウィンドウを開く。基本ウィンドウが小さいまま、別のウィンドウで左右の値を比較できることを確認する。
3. 影、MatCap、リムライトを展開する。内部名・表示名・左右の値・差分状態を確認する。
4. デフォルトで「差分のみ表示」がONになっており、同じ値の行が隠れていることを確認する。OFFに切り替えると全行が表示されることを確認する。
5. 適用先を「右: MatSync_B」にする。影は「左を採用」、MatCapは「右を採用」、リムライトは「変更しない」とする。
6. まだBが変わっていないことを確認し、変更予定のブロックと件数を見て適用する。
7. Bの影だけがAにそろい、BのMatCap・リムライトは維持され、Aも維持されることを確認する。
8. OFF時はBのテクスチャ参照・Tiling／Offsetが保たれる。ONで再比較・採用した場合は、そのブロック内だけテクスチャ設定が転送される。
9. 1回のUndoで適用前に戻ることを確認する。
10. 再比較後に採用選択だけを変更して「比較を終了」を押す。アセットが変化しないことを確認する。

## 5. 比較の外部変更・参照切れ（AC-13）

1. 比較を開いて採用選択を作り、通常のInspectorで左右どちらかの色を変更する。
2. 比較ウィンドウに外部変更の通知が出て、古い比較結果の適用ができなくなることを確認する。
3. 「再比較」を押す。現在値に更新され、採用選択が「変更しない」に戻ることを確認する。
4. 比較中のテストMaterialの一方を削除する場合も、参照切れのまま適用されず、ウィンドウが例外を繰り返さないことを確認する。

## 6. 同時編集の基本（AC-14〜17）

1. A・B・Cの色とMatCap強度を異なる値に戻す。
2. 同時編集モードで元A、先B・Cを設定し、テクスチャOFFで「同期を開始」する。
3. 開始だけではB・Cの色やMatCap強度が変わらないことを確認する。
4. 「同期元をInspectorで開く」を押し、通常のlilToon InspectorでAの色だけを編集する。
5. B・Cの色が追従し、未編集のMatCap強度はそれぞれの値を保つことを確認する。
6. Aの影の使用有無やMatCap強度も変更し、該当項目だけが追従することを確認する。
7. テクスチャOFFのままAのテクスチャ・Tiling／Offsetを変更する。B・Cの設定が保持されることを確認する。
8. 同期を停止し、テクスチャONに変更して再開する。開始だけでは上書きされず、その後Aで変更したテクスチャ設定が同期されることを確認する。
9. 同期中にBだけをInspectorで編集する。A・Cへ逆伝播しないことを確認する。Aで同じ項目を次に編集するとBにもAの新しい値が適用される。

## 7. 同時編集のUndo／Redo（AC-19、AC-21）

1. 同期中にAの数値を1回入力し、B・Cへの反映を待つ。
2. Undoを1回実行し、A・B・Cが編集直前の各値へ戻ることを確認する。待機しても戻した値が再同期で上書きされないことを確認する。
3. RedoでA・B・Cが編集後の値に戻ることを確認する。
4. スライダーを押したまま連続ドラッグして離す。同様にUndoし、1ドラッグが大量の履歴に分割されていないことを確認する。
5. 機能の使用有無を切り替える操作も、関連する値と描画が整合して復元されることを確認する。
6. 何も編集せず待機して、Undo履歴やDirty状態が増えないことを確認する。
7. 通常の選択に加えて、Inspectorをロックした状態でも単一Materialの編集とUndoを確認する。

問題がある場合は、操作したプロパティー名、入力／ドラッグ／機能切り替えの別、Inspectorのロック状態、Undoに必要だった回数を記録する。

## 8. 同期の停止条件（AC-18、AC-20）

それぞれ同期を再開してから、次の操作で停止することを確認する。停止後にAを編集してもB・Cへ反映されないことも確認する。

- 「同期を停止」を押す。
- 同期元・同期先リスト・テクスチャオプションを変更する。
- コピー／比較モードへ切り替える。
- 基本ウィンドウを閉じる。
- Play Modeへ移行する。
- スクリプトの再コンパイル／ドメインリロードを発生させる。再読み込み後に自動再開しない。
- 同期元のシェーダーを切り替える、または同期元のテストMaterialを削除する。
- 同期元を含む複数MaterialをInspectorで同時選択する。

同期先Bのみを削除／未対応シェーダーに変更した場合は、除外理由を表示してCへの同期を続けることを確認する。全同期先が無効になったら停止する。

## 9. 非互換と描画状態（AC-07、AC-08、AC-24）

1. コピー先にStandard等の未対応Materialを含める。理由付きで除外され、有効なlilToonの対象だけ処理されることを確認する。
2. 全対象が不正、元が未指定、または左右が同一の場合、該当する実行ボタンが無効になることを確認する。
3. 通常lilToonとLite等、プロパティー構成が異なるバリアント間でコピー／比較する。不在のプロパティーが除外表示されることを確認する。
4. シェーダーそのもの、Render Queue、描画モード、Override Tagsがコピー元へ強制的にそろわないことを確認する。
5. 同じMultiバリアントのMaterial同士で影・MatCap・発光の使用有無を転送し、Inspectorの値だけでなく実際の表示にも反映されることを確認する。
6. 型やテクスチャ次元の非互換は実装で判定する。該当する環境がある場合、適用不可の理由が表示されることを確認する。

## 10. 保存と書き込み不可（AC-22、AC-25）

1. コピー／比較／同期のいずれかを行い、Unityの通常の保存操作で保存する。プロジェクトを再読み込みし、保存した値が維持されることを確認する。
2. テスト用のコピー先`.mat`だけをOS側で読み取り専用にする。MatSyncで書き込み不可と表示され、他の有効な対象だけ処理されることを確認する。確認後に属性を戻す。
3. FBX等に埋め込まれたMaterialをコピー先に指定した場合、独立した`.mat`が必要と表示されることを確認する。
4. 実行時例外が発生した場合は、結果に失敗・変更済みの範囲が出ること、変更済みの範囲をUndoできることを確認する。例外を発生させるために本番アセットを破損させる操作は不要。

## 確認結果の記録

各項目は未実施の状態で引き渡す。問題があれば、手順番号、左右／元と先のシェーダー名、変更した内部プロパティー名、テクスチャオプション、Consoleのエラー全文を添えると再現箇所を特定しやすい。
