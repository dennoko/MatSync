# MatSync 要件定義書

## 1. 目的と位置付け

MatSyncは、複数のlilToonマテリアルの設定を共通化するUnity Editor拡張である。手動で同じ設定を繰り返す作業を減らしつつ、各マテリアルに固有のテクスチャを維持できることを目的とする。

本書は[overview.md](overview.md)を機能要件、操作仕様、例外処理、受け入れ条件に整理したものである。原案で未指定の動作は、実装の前提が分かるように「暫定仕様」として記載する。既存実装の動作を保証する文書ではない。

### 1.1 仕様の確度

| 区分 | 意味 |
| --- | --- |
| 原案要件 | overview.mdまたは今回の指示で明示された内容 |
| 詳細化 | 原案を一貫して実装・検証するために補った操作や例外処理 |
| 暫定仕様 | 原案だけでは決まらない製品動作。初期実装の案として扱う |

本文の規定は初期実装の要件とし、特に判断の余地がある箇所に暫定仕様と記す。末尾の未確定事項は実装着手時または対応範囲の検証時に確定する。

## 2. 対象範囲

### 2.1 提供する機能

| モード | 用途 | 編集の起点 | 実行方法 |
| --- | --- | --- | --- |
| コピー | 1つのマテリアルの設定を複数へまとめて転送 | コピー元の現在値 | コピーボタンで実行 |
| 比較 | 2つのマテリアルを比較し、機能ブロックごとに値を選択 | 左右の比較結果 | 選択結果を確認して適用 |
| 同時編集 | 通常のInspectorでの編集を複数へ同期 | 同期元の変更 | 同期中に変更を検出して反映 |

### 2.2 初期実装の対象外

- ランタイムでの同期、アバターへの実行時コンポーネントの追加。
- lilToon以外のシェーダーとの相互変換。
- Rendererのマテリアル割り当て変更、マテリアルの自動複製、テクスチャ画像自体の加工。
- 比較結果から第3のマテリアルを新規作成する機能（暫定仕様）。
- プリセット、履歴の永続保存、シーンをまたいだ自動同期。
- 完成版の装飾、独自テーマ、細かなレイアウト調整、USSによる外観の実装。

## 3. 用語とデータの扱い

| 用語 | 定義 |
| --- | --- |
| 基本ウィンドウ | 3モードの切り替え、マテリアル指定、実行・停止を行う小さいEditorWindow。Unity上でタブとして配置できるもの |
| 比較ウィンドウ | 比較中に開く、左右の値と採用選択を表示する別のEditorWindow |
| コピー元／同期元 | 設定の取得元となる単一のマテリアル |
| コピー先／同期先 | 値を書き込む1件以上のマテリアル |
| 機能ブロック | 影、MatCap、リムライトなど、lilToonの機能単位でまとめたプロパティー群 |
| テクスチャ設定 | テクスチャ参照、およびそのスロットに属するTiling／Offset |
| マテリアル設定 | 数値、色、ベクトル、機能の有効状態など。適用範囲の詳細は第5章で定義する |

マテリアル指定はアセットそのものへの参照として扱う。Hierarchyから取得した場合もRendererの共有マテリアル参照を使用し、取得操作によってインスタンスを生成しない。同じアセットを使う他のオブジェクトにも変更が反映されることを、実行領域付近の短い説明で示す。

## 4. 共通のマテリアル指定要件

### MAT-01：直接指定

- Project上のMaterialアセットをドラッグ＆ドロップして指定できる。
- 単一指定欄ではObjectField相当の選択操作ができる。
- 複数指定欄ではリストを表示し、複数アセットを一度に追加できる。
- 各行にマテリアル名と参照を表示し、対象をProject上で確認できる。

### MAT-02：Hierarchyからの抽出

- Hierarchyのメッシュを持つGameObjectをドロップすると、Rendererに割り当てられたマテリアルを候補として抽出する。
- 複数GameObjectの同時ドロップに対応する。
- MeshRendererとSkinnedMeshRendererを対象とし、全マテリアルスロットを確認する。
- 子オブジェクトも抽出対象に含め、非アクティブなGameObjectも対象とする（暫定仕様）。
- マテリアルがないオブジェクトや空のスロットは無視し、追加できなかった理由を簡潔に表示する。
- 抽出だけではマテリアルの値やRendererの割り当てを変更しない。

### MAT-03：単一欄へ複数候補を渡した場合

- コピー元、同期元、比較の左右はそれぞれ1件だけ指定できる。
- 抽出結果が1件なら直接設定する。
- 複数候補がある場合は候補一覧から1件を選択する。先頭の候補を無断で採用しない。
- 選択を取り消した場合、元の指定を維持する。

### MAT-04：複数対象の整理

- 同じMaterial参照は重複登録しない。同名でも異なるアセットは別として扱う。
- 追加後に行単位で削除でき、リスト全件のクリアもできる。
- 不要なサブメッシュ用マテリアルは、この削除操作で対象から除外できる。
- コピー元／同期元と同一のマテリアルは転送対象から除外する。
- 無効・未対応の項目には理由を表示し、実行可能な対象件数を分かるようにする。
- 削除・クリアは対象リストだけを変更し、アセットは削除しない。

## 5. 共通の転送ルール

### PROP-01：基本対象

- 初期対応対象はlilToonマテリアルとする。
- Float、Range、Color、Vector、および数値プロパティーとして表現された有効・無効状態を転送する。
- 整数型など、採用するUnity／lilToon環境で必要となる追加の型は互換性調査で対象を確定する。
- プロパティーの対応付けには表示名ではなく内部名を使用する。
- コピー元とコピー先の両方に存在し、型および意味に互換性のある項目を処理する。
- コピー先だけに存在する設定は維持する。不足・型不一致・未対応の項目は理由付きでスキップする。

### PROP-02：テクスチャの保護

- 全モードで「テクスチャを含める」オプションの初期値をOFFにする。
- OFFでは、書き込み先のテクスチャ参照を保持する。
- Tiling／OffsetもOFF時には保持する（暫定仕様）。同じスロットの設定として参照と一緒に扱う。
- ONでは、対象となったテクスチャ参照とTiling／Offsetを転送する。参照が未設定なら未設定の状態も転送する。
- テクスチャに関連する色、強度、使用有無などの独立した数値プロパティーは、OFFでも転送対象とする。
- OFFでテクスチャを保持したまま機能の使用有無だけ変わり、見た目が変化することは許容する。
- テクスチャ画像アセット自体を複製・変更しない。

### PROP-03：シェーダー固有状態

- シェーダーそのものの変更は初期実装の転送対象外とする（暫定仕様）。
- Shader Keywords、Render Queue、Override Tags、描画パスの有効状態などは、プロパティーと区別して扱う。
- これらをコピー元から一括転送せず、採用した設定に必要な状態調整がある場合は、対応バージョンに適した方法で整合させる。
- 描画モード変更など、シェーダーの差し替えが必要な操作を安全に反映できない場合は、関連項目をまとめて未対応と表示する。
- 内部管理値、派生値、非表示項目を無条件で転送しない。対応表で転送・再計算・除外を分類する。
- 異なるlilToonバリアント間は対応表で互換性を確認できる範囲だけ処理し、完全な見た目の一致は保証しない。

### PROP-04：実行時の検証と結果

- 実行直前に参照、lilToon対応状況、書き込み可否を再検証する。
- コピー元が不正なら処理を開始しない。コピー先が一部不正な場合は該当項目を除外し、有効な対象には適用できる。
- 値が同じ項目には不要な書き込みを行わない。
- 結果には変更したマテリアル数、変更なしの数、スキップ・失敗の数と理由を表示する。
- 途中で例外が発生した場合は後続の処理を停止し、既に変更した範囲を表示する。変更済みの範囲はUndoで戻せるようにする。
- 自動的にシェーダーを置き換えたり、対象外アセットの読み取り専用状態を解除したりしない。

## 6. コピー モード

### COPY-01：基本UI

- コピー元1件、コピー先リスト、テクスチャを含めるチェック、コピーボタンを表示する。
- マテリアル指定には第4章の操作を使用する。
- コピー元が未指定・不正、または有効なコピー先が0件なら実行ボタンを無効にし、理由を表示する。

### COPY-02：適用

- ボタンを押した時点のコピー元の設定を、各コピー先に適用する。
- 第5章の転送対象をまとめて処理する。初期実装では項目ごとの選択UIを必須としない。
- コピー元は変更しない。
- コピー先ごとにテクスチャ保持のルールを適用し、各コピー先固有のテクスチャを維持する。
- 1回のコピーによる全対象への変更は、1回のUndoで元に戻せる。

### COPY-03：操作の流れ

1. コピー元を指定する。
2. コピー先を直接指定するか、複数メッシュから抽出する。
3. 不要な対象をリストから削除する。
4. 必要ならテクスチャを含める設定を変更する。
5. コピーボタンで適用し、結果を確認する。

## 7. 比較モード

### COMP-01：開始とウィンドウ

- 基本ウィンドウでは、左マテリアル、右マテリアル、比較開始ボタンを表示する。
- 両方が有効な異なるマテリアルの場合に比較を開始できる。
- 比較開始時に専用の比較ウィンドウを生成し、基本ウィンドウは小さいまま維持する。
- 初期実装では同時に開く比較セッションは1つとする（暫定仕様）。
- 比較終了時は比較ウィンドウを閉じる。終了操作だけで未適用の変更を書き込まない。

### COMP-02：左右表示とブロック

- 左右にマテリアル名と値を並べ、同じプロパティーを同じ行で比較できる。
- 影、MatCap、リムライトなどの機能ブロックごとに表示をまとめる。
- ブロックを折りたたみ可能にし、各ブロックに差分の有無と採用状態を表示する。
- ブロック内では表示名、左右の値、不在・未対応の状態を確認できる。
- テクスチャ参照の差分はオプションがOFFでも表示できるようにし、適用対象外であることを示す。
- 型ごとに差分判定の方法を統一し、丸めた表示が同じ場合でも内部値の差分があると分かるようにする。
- 片側だけにあるプロパティーは欠落状態を示し、適用可能とは扱わない。
- 機能ブロックの候補は基本色、ライティング、影、発光、ノーマル、反射、MatCap、リムライト、輪郭線、透過・描画設定、その他とする。正式な分類は対応するlilToonの構成に合わせて確定する。

### COMP-03：採用と適用先（暫定仕様）

- 比較結果の適用先は「両マテリアル（相互に反映）」「左のみ」「右のみ」から選択する。初期値は「両マテリアル」とする。
- 各ブロックは「変更しない」「左を採用」「右を採用」から選択し、初期値は「変更しない」とする。
- 左右の採用は値の取得元を示し、適用先とは独立して扱う。
- ブロックで採用した側の設定を、反対側のマテリアルの同じブロックに反映する。「両マテリアル」ではブロックごとに採用した側から反対側へ反映するため、左右の両方が変更されうる。
- 「変更しない」のブロックは左右とも現状を維持する。「左のみ」「右のみ」で適用先自身を採用した場合は実質変更なしとする。
- 適用先に含まれないマテリアルは変更しない。
- 描画設定ブロックは、シェーダーまたは`_TransparentMode`（Multiの描画モード）が左右で異なる場合は適用しない。
- 適用前に、適用先名、変更するブロック、テクスチャの扱いを確認できる。

### COMP-04：テクスチャ

- 比較ウィンドウに「テクスチャを含める」オプションを用意し、初期値をOFFにする。
- OFFでは、どちらを採用しても適用先マテリアルのテクスチャ設定を維持する。
- ONでは、採用する側のテクスチャ設定を、そのブロックに限って適用する。
- ブロック外の項目や「変更しない」のブロックには影響させない。

### COMP-05：適用と再比較

- 採用選択だけではアセットを変更しない。適用ボタンで初めて反映する。
- 比較開始時の値を保持し、適用直前に左右のマテリアルが外部で変更されていないか確認する。
- 外部変更がある場合は適用を停止し、再比較を求める。再比較では採用選択をリセットする（暫定仕様）。
- オプション変更時は、変更予定の表示を更新する。
- 適用後は現在値で再比較し、採用選択をリセットする。
- 1回の適用による変更は、1回のUndoで元に戻せる。

## 8. 同時編集モード

### SYNC-01：基本UI

- 同期元1件、同期先リスト、テクスチャを含めるチェック、同期開始／停止、現在の同期状態を表示する。
- ツール内に独自のマテリアルプロパティー編集UIを作らない。
- プロパティー編集は通常のMaterial Inspectorに任せる。
- 同期元を選択してInspectorで確認する操作を用意する。
- 同期中であることと、有効な同期先の件数を基本ウィンドウで確認できる。

### SYNC-02：開始と反映（暫定仕様）

- 同期開始は明示的な操作で行う。モードを選んだだけでは同期しない。
- 開始時点の同期元を基準値として保持し、開始操作だけでは既存の同期先を上書きしない。
- 以後、同期元で変更された対応プロパティーだけを同期先へ反映する。
- 同期元で変更されていないプロパティーは、同期先ごとの値を維持する。
- 変更はUnity Editorの更新処理で検出し、通常操作で継続的な手動更新を必要としない。
- 同期のためにInspectorのフォーカスを奪わず、編集中の入力操作を妨げない。
- Inspectorが1操作で変更する関連プロパティーや派生状態も、対応範囲内で整合した単位として扱う。
- 初回に全設定をそろえたい場合は、コピー モードを使用する。

### SYNC-03：同期の方向と競合

- 同期方向は同期元から同期先への一方向とする。
- 同期先を直接編集しても、その変更を同期元や他の同期先へ逆伝播させない。
- 同期先の直接編集は、同期元で同じ項目が次に変更されるまでは維持する（暫定仕様）。
- ツールによる書き込みを新たなユーザー編集として再処理せず、循環更新を防ぐ。
- 同期元を含むInspectorの複数マテリアル編集は初期実装の対応対象外とする（暫定仕様）。検出できる場合は同期を一時停止して理由を表示する。
- 同期対象を含む比較の適用・コピーと同時に実行しない。該当操作の前に同期を停止する。

### SYNC-04：停止と設定変更

- 同期停止後は同期元の編集を同期先へ反映しない。既に適用した変更は維持する。
- 同期元、同期先、テクスチャオプションを変更する場合は同期を停止し、再開を明示操作にする（暫定仕様）。
- モード切り替え、基本ウィンドウのクローズ、Play Modeへの遷移、スクリプト再コンパイル／ドメインリロード時には同期を停止する。
- 再読み込み後に同期状態を自動復帰させない。
- 同期元が消失・未対応になった場合は同期を停止する。
- 同期先の一部が無効になった場合はその対象を除外し、残りで継続する。有効な同期先が0件なら停止する。

### SYNC-05：Undo／Redo

- Inspectorでの同期元の編集と、それに伴う同期先への変更を、可能な限り同じ操作単位でUndo／Redoできるようにする。
- スライダーのドラッグなど1つの編集操作を、更新フレームごとに大量のUndo履歴へ分割しない。
- Undo／Redoで戻った値を新規編集として再同期し、復元を打ち消してはならない。
- Undo／Redo後は同期元の基準値を更新し、次のユーザー編集から同期を再開する。
- 通常のInspectorとのUndoグループ統合方法は実装前に検証する。統合できない操作については動作と制約を明示し、不整合を残さない。

## 9. UI・構成要件

### UI-01：初期UI

- 初期UIは標準の入力欄、リスト、チェックボックス、ボタン、折りたたみ、スクロール領域で構成してよい。
- 基本ウィンドウには指定欄と主要操作を中心に配置し、全プロパティーの一覧は表示しない。
- 対象リストが長くなっても、スクロールによって実行・停止操作へ到達できる。
- 比較ウィンドウは左右の対応関係と採用状態の読みやすさを優先する。
- 無効な操作はボタンの無効化と短い理由表示で案内する。
- 通常のコピーや同期のたびに確認ダイアログを出す必要はない。対象と適用範囲は操作前にUI上で確認できるようにする。

### UI-02：後続のUSS移行

- 今回は簡易UIとし、USSによる外観の実装・調整は後工程とする（ユーザー指示）。
- 初期UIの実装方式は固定しない。IMGUIでも簡素なUI Toolkitでもよい。
- マテリアル抽出、プロパティー取得・分類、差分計算、変更計画、適用、Undo、同期状態の管理を描画コードから分離する。
- UIは選択状態の入力と結果表示を担い、UIを書き換えずに処理部分を検証できる構成にする。
- 後からUI Toolkit／USSへ移行しても、機能ブロックの定義と転送処理を再利用できるようにする。
- USSへの移行に必要な将来の画面設計やクラス名の詳細は、本書の対象外とする。

## 10. 非機能要件

### NFR-01：Editor限定

- 実装はEditor専用として配置し、ビルドやアバターのランタイムに含めない。
- UnityおよびlilToonの対応バージョンを明示する。VRChat SDKとの連携を機能成立の必須条件にしない。

### NFR-02：変更と保存

- 変更したMaterialをDirtyとして扱い、Unityの通常のアセット保存で永続化できるようにする。
- 同期更新ごとにプロジェクト全体の保存・再インポートを実行しない。
- 未変更アセットや処理対象外のアセットを保存目的で変更しない。
- Undo／Redoによる復元後も、保存対象の状態を正しく維持する。

### NFR-03：応答性

- 同期停止中は継続的なマテリアル走査をしない。
- 同期中は登録された同期元と同期先だけを扱い、毎フレームのプロジェクト全体走査をしない。
- 差分がない更新ではMaterialの書き込み、Dirty化、Undo登録を行わない。
- プロパティー定義やブロック分類など再利用できる情報をキャッシュする。
- 同期の遅延や対象数の性能目標は、対応環境と代表的なアバターのマテリアル数を決めて測定後に確定する。

### NFR-04：エラーと診断

- lilToonが未導入・未対応の場合は、操作不能の理由を示す。
- 参照切れ、未対応シェーダー、書き込み不可、プロパティー不一致を区別して表示する。
- 同じエラーを更新フレームごとにConsoleへ出力しない。
- エラー後もウィンドウを操作でき、対象の除外や同期停止ができる。

## 11. 受け入れ条件

対応するUnity／lilToon環境で、異なる数値・テクスチャを設定した複数のテスト用マテリアルを使って確認する。

| ID | 確認内容 | 合格条件 |
| --- | --- | --- |
| AC-01 | Materialの直接追加 | 単一元と複数先を指定でき、重複参照は1件として扱われる |
| AC-02 | 複数メッシュの同時ドロップ | MeshRenderer／SkinnedMeshRendererの複数スロットから候補を抽出し、不要な項目を削除できる |
| AC-03 | 単一欄への複数候補 | 選択UIが表示され、選択するまで指定が勝手に変わらない |
| AC-04 | 標準コピー | 数値・色・ベクトル・有効状態が反映され、各コピー先のテクスチャ参照とTiling／Offsetが保たれる |
| AC-05 | テクスチャ込みコピー | 参照、未設定の状態、Tiling／Offsetもコピー元にそろう |
| AC-06 | コピーのUndo／Redo | 複数コピー先が1回のUndoで復元され、Redoで再適用される。コピー元は変わらない |
| AC-07 | 無効な対象 | 不正なコピー元では開始できず、不正なコピー先は理由付きで除外される |
| AC-08 | プロパティーの非互換 | 不在・型不一致の項目がスキップされ、対応している項目だけが反映される |
| AC-09 | 比較表示 | 別ウィンドウで左右の値と機能ブロックごとの差分を確認でき、基本ウィンドウは拡大されない |
| AC-10 | ブロック採用 | 指定した適用先だけが選択内容に従って変わり、「変更しない」のブロックは維持される |
| AC-11 | 比較時のテクスチャ保護 | OFFでは適用先の参照とTiling／Offsetを保持し、ONでは採用ブロック内の設定だけ反映される |
| AC-12 | 比較の中断とUndo | 適用せず閉じても変更されず、適用後は1回のUndoで復元できる |
| AC-13 | 比較中の外部変更 | 古い比較結果で上書きされず、再比較が必要と表示される |
| AC-14 | 同期開始 | 開始だけでは同期先の既存値が変わらない |
| AC-15 | Inspectorからの同期 | 同期元で編集した項目が全有効同期先へ反映され、未編集項目は各同期先の値を保持する |
| AC-16 | 同期のテクスチャ設定 | OFFではテクスチャ設定の変更を同期せず、ONでは変更したテクスチャ設定を同期する |
| AC-17 | 一方向同期 | 同期先の直接編集が同期元・他の同期先へ伝播しない |
| AC-18 | 同期停止 | 停止、モード変更、ウィンドウ終了、Play Mode移行、ドメインリロード後に同期が続かない |
| AC-19 | 同期のUndo／Redo | 単一入力とスライダードラッグについて、元と先の値を整合して復元でき、Undo後の再同期で復元が打ち消されない |
| AC-20 | 同期中の対象消失 | 同期元消失なら停止し、同期先の一部消失なら除外を通知して残りで継続する |
| AC-21 | 無変更時の動作 | 同じ値の再コピーや同期中の待機で不要な変更・Undo履歴が増えない |
| AC-22 | 保存 | 実行後にUnityで保存して再読み込みすると適用値が維持される |
| AC-23 | アセット参照 | Hierarchyからの追加でMaterialが複製されず、Rendererの割り当ても変わらない |
| AC-24 | 描画状態の整合 | 対応する有効状態の切り替えが実際の描画に反映され、シェーダー変更を要する未対応操作は除外表示される |
| AC-25 | 書き込みエラー | 書き込み不可の対象を理由付きで扱い、途中失敗時も変更範囲を把握してUndoできる |

## 12. 実装前に確定・検証する事項

| 項目 | 現時点の方針／確認事項 |
| --- | --- |
| 対応環境 | UnityとlilToonの最低・推奨バージョンを確定する |
| 対応シェーダー | lilToonの各バリアントとバリアント間の転送可能範囲を確認する |
| プロパティー対応表 | 内部名、型、機能ブロック、転送可否、関連する状態調整を一覧化する |
| 描画モード | シェーダー変更を要する項目と、プロパティーだけで安全に扱える項目を区別する |
| 比較の適用先 | 両マテリアル（初期値）・左のみ・右のみから選択する。新規マテリアル生成が必要なら追加仕様とする |
| テクスチャの境界 | 初期案ではTiling／Offsetも保護する。独立したUV関連数値は通常の数値として扱い、例外を対応表で定める |
| Hierarchyの抽出範囲 | 初期案は子階層と非アクティブを含む。操作感を確認する |
| 同期の変更検出 | 通常のlilToon Inspectorの編集とUndo／Redoを区別できる手段を検証する |
| 同期のUndo単位 | Inspectorの単一入力、連続ドラッグ、機能切り替えのそれぞれで整合性を確認する |
| 性能 | 代表的な対象数と測定環境を決め、操作を妨げない更新頻度・遅延の数値目標を設定する |

## 13. 推奨する実装順序

1. 対応環境、プロパティー分類、転送範囲を調査し、共通の変更処理とUndoを実装する。
2. 簡易UIでマテリアル指定、Hierarchy抽出、コピー モードを実装する。
3. 左右比較、機能ブロックごとの採用、適用を実装する。
4. Inspectorの変更検出とUndo統合を検証し、同時編集モードを実装する。
5. 全モードの受け入れ条件を確認し、対応範囲と制約を記録する。
6. 後工程でUI Toolkit／USSへUIをリファクタリングする。
